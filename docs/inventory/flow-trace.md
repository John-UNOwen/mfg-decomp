# Flow Trace: boot -> ea3 service -> card login -> lobby -> match (Mahjong Fight Girl, VFG)

Method: read-only trace of decompiled C# under `api/recovered/` (Assembly-CSharp, Assembly-CSharp-firstpass, kamunity). Every line cite is repo-relative and was read by this trace or by a delegated subtrace that quoted the read lines (cross-checked where load-bearing). `[OBSERVED]` = the call/line was seen in code. `[INFERRED]` = conclusion drawn from evidence, not seen as a literal call. No DSH/git operations were performed. The game install itself is out of scope; where launch-log order is quoted it comes from `docs/01-spice2x-findings.md`.

Big picture (verified): the game has two independent server surfaces:
1. e-Amusement / eAC3 surface: native `kamunity.dll` exports reached via LoadLibraryA/GetProcAddress, wrapped by `api/recovered/kamunity/KAMUNITY/`. Carries XRPC (`vfgac`, `vfglog`, `cardmng`, `uploader`), PASELI/eacoin, PCB POS events, ea3 status, license report. `[OBSERVED]`
2. TCS front-server surface: plain HTTP POST returning XML (`MFG.GameRequest/RequestApiBase` -> `Konami.System.Net`), base URL `SystemConfigGameData.FrontServerUrl`. Carries login, all player userdata, matchmaking, and the entire mahjong command log. `[OBSERVED]`

## 3. LobbyLoop

Boot-level effect: `Kamunity.Startup()` is never called (`ResidentFlow.cs:228` gate), so no avs2 binding, no ea3 boot wait (`BootSceneFlow.cs:347-351` NetworkItem auto-PASS), no SystemUtility/CabinetManager init from ea3 (`ResidentFlow.cs:555-559` gate `KamunityInstance.isActive`), no NetworkConfirm reroute (requires `KamunityInstance.isActive`, `ResidentFlow.cs:745-748`), no pcbtracker license flow. `IkeyDevice` checks skip (`IkeyDevice.cs:15/:46`). `[OBSERVED]`

What replaces eAC3 for networking (the important part):
- Base URL selection: `SystemConfigGameData.FrontServerUrl` getter returns `NetEnvironment.Instance.Connection.RequestUrl` whenever kamunity boot is disabled (`api/recovered/Assembly-CSharp/SystemConfigGameData.cs:34-48`); `NetEnvironment.Initialize` picks `NetEnvironmentConnection.DefaultKonamiNet` in that mode (`api/recovered/Assembly-CSharp/Konami.System.Net/NetEnvironment.cs:23-33`); the constants are hardcoded AOG gateway URLs (`api/recovered/Assembly-CSharp/Konami.System.Net/NetEnvironmentConnection.cs:16-48`): default `https://rproxy0400.ea.konami.net/aog` (eAC3 prod, eAC3-dev `http://rproxy0400.pvt.ea.konami.net/aog`), KonamiNet `https://aog03-stg.pvt.mo.konami.net/aog` (ALL.net Open Gateway staging, with its own proxy profile `NetEnvironmentProxy.DefaultKonamiNet`). `[OBSERVED]` In kamunity mode the same seam is used but its URL is overridden by the `vfgac.service_list` discovery (`CardEntryScene.cs:1070-1088`, `TitleDemoUtility.cs:245-260` choose XRPC vs NetEnvironment by the same flag). `[OBSERVED]`

Can the full game run in this mode without kamunity? `[OBSERVED]` every component of the pipeline is reachable in KonamiNet mode: boot checks pass (NetworkItem `:347-351`), login chain is pure front-server HTTP (`GameDataManager.cs:125-175`), lobby loops are the same workers (ea3 status sampling short-circuits to ONLINE, `GameUtility.cs:433-441`), matching/play is pure HTTP (`/entry_game`, `/gget`, `/gpost`, `/end_game`), result saves are pure HTTP. Only eAC3-side behaviors are disabled: card inquiry/PIN binding, PASELI, PCB/PP accounting, pcbtracker license, package/online-update (native AvsPackage, `OnlineUpdateMessage.cs:67` gate). `[INFERRED]` conclusion: yes, login + gacha + matches can run without kamunity on the game's own HTTP seam (this is evidently Konami's own dev/QA connection mode, evidenced by `IsEamDevConnection` defaults true in this mode `GameUtility.cs:361-366` and the staging URL `NetEnvironmentConnection.cs:40-48`); billing and card-account provisioning are out of the picture in it.

Port consequence: `[INFERRED]` the browser port does not have to reproduce the eAC3 wire protocol to get gameplay: it can implement the front-server HTTP surface (35 endpoints + gget/gpost command log, section 5 appendix) which the game already treats as the gameplay authority. eAC3/XRPC (`vfgac`/`vfglog`/`cardmng`) and eacoin are needed only for card identity, PIN, and POS accounting, which KonamiNet mode demonstrates the game itself can run without. Strongest citations for that verdict: `NetEnvironment.cs:23-33`, `SystemConfigGameData.cs:34-48`, `RequestCoroutine.cs:132-160`, `RequestApiBase.cs:87-97`.
